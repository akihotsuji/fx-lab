# JForex導入・観測

## ローカル実行

このコードはJForexの **IStrategy** として実装した観測器です。一般のインジケーター一覧に追加する形式ではありません。API 2.13.99でコンパイルを検証しました。実際のJForex画面での動作確認はまだ行っていません。

1. デスクトップ版JForexをデモ口座で起動します。
2. リポジトリの `jforex/WemofObserver.java` をダウンロードします。ファイル名は変更せず、UTF-8で保存します。
3. ローカルストラテジーの編集画面からファイルを開き、コンパイルします。UIの表記はJForexの版によって異なります。
4. USD/JPYの5分足チャートを開きます。価格側はBidを選択し、必要なら通常のボリンジャーバンド20・±3σも追加します。
5. ローカルで開始し、設定画面を確認します。最初は標準値のままで観測します。
6. コンソールに `WEMOF observation only; NO ORDERS. Files:` と保存先が出ます。開始直後に直前19本の完成した5分足を取得し、`seed.csv` に保存します。
7. 正常停止すると未解決の観測をENDとして記録し、ファイルを閉じます。設定変更は停止して再起動し、セッションを分けてください。

この版は注文APIを呼びません。リモート実行ではなくローカルで使用してください。ログ保存とチャート描画を前提にしています。

## 表示

| 表示 | 意味 |
| --- | --- |
| BUY / SELL | その5分区間で最初に受信した±3σ接触の仮想入場 |
| RESULT TP | 決済側価格で3pips以上の戻りを初めて観測 |
| RESULT SL | 決済側価格で10pips以上の逆行を初めて観測 |
| RESULT TIME | 接触から15分以降の最初の受信価格で分類 |
| RESULT GAP | 更新空白が60秒を超えたため結果不明 |
| SKIP SPREAD | 有効にしたスプレッド上限を超え、接触を見送り |
| オレンジの線 | 現在の5分区間の接触境界（通常のBB線と異なる） |

最新200件のラベルを描画します。CSVには全件を保存します。複数のUSD/JPY 5分チャートがある場合、最初に取得したものへ描画します。対応するチャートがなくても観測とCSV保存は続きます。チャートを後から開いた場合、次の5分区間または次のイベントで表示が更新されます。

## 過去ティック再生

JForexのHistorical Testerでこのストラテジーを選び、USD/JPY・ティックを使用する再生モードを選択します。可視化のチャートは5分で構いません。1分OHLCから作る疑似ティックのモードは、足内順序の問題を解決しません。利用可能な履歴・選択肢は環境で確認してください。

このストラテジーは注文しないため、テスターの標準的な取引損益レポートには売買成績が出ません。**分析する結果はこのストラテジーのevents.csvです。** スプレッドを計測するにはBid・Askの両方が履歴に必要です。

## フォワード観測とPython比較

ローカルで稼働している間の受信ティックを保存します。`recordTicks=true` にしてください。停止後、READMEの再生コマンドへそのセッションの4ファイルを指定すれば、JavaのログとPythonのログを比較できます。

実ティックのすべてが受信できる保証はありません。JForexにはonTick処理中の更新が間引かれる実行仕様があります。履歴取得、描画、ファイル入出力も処理時間を要するため、GAPにならない短い間引きでも動きの一部を見逃す可能性があります。CSVの一致は **同じ受信列に対する判定の一致** を示し、全市場ティックや実際の約定を検証するものではありません。

ログは通常1秒ごと、イベントがあるときはその都度フラッシュします。異常終了では末尾の未保存データやENDが欠ける可能性があります。再起動すると新しいセッションになり、以前の仮想ポジションは引き継ぎません。
