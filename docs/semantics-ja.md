# 判定仕様 v1

## 基準と接触

価格はUSD/JPY、1pip=0.01円です。5分区間はUTC Unix時刻を300,000msで切り捨てます。BBは現在のBidを終値とする20本・母標準偏差です。

直前19本の完成足の平均をm、母分散をvとすると、現在のBidがBBの±3σに等しくなる境界は `m ± 3 × sqrt(20v / (19−9))` です。この境界を5分区間の間固定し、受信Bidの到達または越境を接触とします。v=0のときは接触を出しません。期間・偏差を変える場合は `期間−1 > 偏差²` が必要です。

初期値は最初のティックより前に完成したBidの5分足を履歴から取得します。その後の完成終値は各5分区間の最後の **受信Bid** です。欠けた区間の足を補間しません。前営業日の完成足も本数に数えます。履歴終値と受信列の終値に差がある可能性はあります。seedが不足した場合は最初の部分足を捨て、必要な完成足が貯まるまで接触を出しません。

各5分区間で最初の接触を1件だけ数えます。上側で売り、下側で買い。越境の場合も境界の理想価格ではなく実際の受信価格を使います。開始時点ですでに境界外なら最初の受信ティックを接触とします。区間ごとの独立したシグナル観測のため、観測期間が重なると複数件を同時に追跡します。これは単一ポジションの資金管理ではありません。

## 価格・判定順序

`BID_ASK` は買いAsk→Bid、売りBid→Askです。スプレッドは決済可能価格との差としてすでに含まれます。`BID_REFERENCE` は両方向ともBidで入りBidで判定します。追加往復コストは結果から一度だけ控除し、TP/SLの到達判定には使いません。

受信ティックごとの順序は次の通りです。

1. 不正な価格・逆転Ask/Bid・過去へ戻る時刻をQUALITYとして棄却。状態を進めない。
2. 既存の観測に対して、直前の有効ティックから60秒超ならGAP。損益は空欄。
3. GAPでなければMAE/MFEを更新。期限到達をTIMEとして優先し、その後TP、SLを判定。
4. 新しい5分区間なら境界と接触フラグを更新。
5. 初回接触ならスプレッド上限を確認。超過はSKIPで、その区間の接触を消費。
6. 採用した接触をTOUCHとして記録。入場スプレッドだけでSL幅に達していれば同じティックでSL。

同じミリ秒のティックは受信行順を維持します。OHLCの高値・安値から順序を推測しません。閾値比較には1e−6pipの丸め許容を使います。

TP/SLの損益は閾値の3pips/−10pipsに固定せず、そのときの決済側受信価格を使います。価格が飛べば超過します。TIMEも期限ぴったりの補間価格ではなく期限以降の最初の受信価格です。更新空白が上限を超えた場合はTIMEよりGAPを優先します。

停止時に未解決ならEND、損益は空欄です。GAP/ENDは勝率・確定損益から除外する際に件数も併記してください。未知の結果を0pipsとして足すと評価を歪めます。TP率とコスト込み損益は別の指標です。

## Pine v2.1との違い

`pine/wemof-observer-v2.1.pine` は移植前の比較資料です。その履歴側は1分OHLCによる順序不明を含み、LIVE側はTradingViewの更新価格で観測します。JForex版はBid/Askの受信列を使うため、両者の件数・損益がそのまま一致する設計ではありません。特にPineの追加コスト0.3pipsに対し、JForex標準値は追加0・実スプレッド込みです。比較時は価格モデル・コスト・期間・データ配信を揃えてください。

この版では、反転を待つ条件、レジスタンス、ラウンドナンバー、ピボット、経済指標の除外は実装していません。まず接触直後の動きを記録する基準モデルを用意し、以降の条件変更を比較できるようにしています。
